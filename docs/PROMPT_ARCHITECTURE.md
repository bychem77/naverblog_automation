# 프롬프트 문서 구조와 수정 원칙

## 단일 기준

현재 운영 규칙의 원본은 `prompts/BYCHEM_NAVERBLOG_MASTER_PROMPT.md` 하나다.

본문 분량, 문체, 폰트, 크기, 정렬, 여백, 이미지 개수, 스티커, 게시물 하단 순서, 태그와 공개 상태처럼 결과물을 바꾸는 규칙은 마스터 프롬프트에서만 결정한다.

## 문서별 역할

| 문서 | 역할 | 현재 규칙을 바꿀 수 있는가 |
|---|---|---|
| `prompts/BYCHEM_NAVERBLOG_MASTER_PROMPT.md` | AI가 따라야 할 전체 제작 규칙 | 예 |
| `prompts/이미지생성_캐릭터활용_프롬프트.md` | 캐릭터 정체성·장면 구성·이미지 품질 보완 | 아니요 |
| `docs/WORKFLOW.md` | 사람이 확인할 작업 단계와 승인 시점 | 아니요 |
| `docs/발행운영규칙.md` | 카테고리 판단과 운영 설명 | 아니요 |
| `templates/` | 입력·산출물의 빈 형식 | 아니요 |
| `examples/` | 과거 작업 예시 | 아니요 |
| `docs/CHANGELOG.md` | 과거 변경 이력 | 아니요 |

## 충돌할 때 적용 순서

1. 현재 작업에서 사용자가 명시한 최신 지시
2. 마스터 프롬프트의 현재 버전
3. 이미지 보조 프롬프트의 범위 내 세부 규칙
4. 운영 문서와 템플릿
5. 예시와 변경 이력

하위 문서에 다른 숫자나 형식이 남아 있더라도 섞거나 평균 내지 않는다. 상위 규칙 하나만 적용한다.

## 규칙을 변경하는 방법

1. 마스터 프롬프트의 해당 항목을 먼저 수정한다.
2. 마스터 프롬프트 버전과 최종 개정일을 올린다.
3. 변경 이력에 변경 이유와 결과를 기록한다.
4. 보조 문서는 가능하면 숫자나 서식을 다시 쓰지 않고 마스터의 해당 절을 참조하게 한다.
5. `scripts/check_prompt_consistency.sh`를 실행해 알려진 충돌과 이전 값을 확인한다.
6. 검수 후 커밋하고 GitHub `main`에 푸시한다.

## 주의

- 변경 이력의 과거 값은 당시 기록일 뿐 현재 지침이 아니다.
- 예시 원고는 제작 당시 버전의 결과물이므로 새 글 작성 규칙으로 복사하지 않는다.
- GitHub에서 마스터 프롬프트를 직접 수정했다면 다른 작업을 시작하기 전에 최신 내용을 먼저 가져온다.
