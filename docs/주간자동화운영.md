# 바이켐 블로그·카드뉴스 주간 자동화 운영

## 1. 실행 일정

- 요일: 매주 화요일·목요일
- 시간: 오전 9시
- 기준 시간대: Asia/Seoul
- 회차별 게시물: 1건
- 네이버 게시 상태: 비공개

## 2. 회차별 작업 순서

1. `prompts/BYCHEM_NAVERBLOG_MASTER_PROMPT.md`와 최신 운영 문서를 읽는다.
2. 승인된 콘텐츠 캘린더, 기존 발행 기록과 `examples/`를 확인해 중복 주제를 피한다.
3. 캘린더의 예정 미발행 주제를 우선 사용한다. 예정 주제가 없으면 마스터 프롬프트의 범위에서 새 주제를 정한다.
4. 최신 공식 원자료로 전문용어·수치·안전·법령 내용을 확인한다.
5. 블로그 원고와 이미지를 제작한다. 기본 구성은 대표사진 1컷, 캐릭터 본문 이미지 1컷, 기술 이미지 또는 인포그래픽 1컷이며 세 번째 이미지는 설명 가치가 있을 때만 사용한다.
6. 도입·질문·기술 설명·체크리스트·요약·마무리 중 문맥에 맞는 위치가 있으면 승인된 네이버 스티커 1개 사용을 우선 검토한다. 적합한 위치가 없으면 생략한다.
7. 네이버 편집 규칙·카테고리·태그·이미지 중복·UI 잔여 문구를 검수한다.
8. 네이버 블로그에 반드시 비공개로 게시한다.
9. 게시물의 핵심 내용을 요약한 모바일용 카드뉴스 PNG 세트를 제작한다.
10. 원고·이미지·카드뉴스를 `examples/YYYY-MM-DD_주제_상태/` 아래에 함께 저장한다.
11. 비공개 게시가 성공하면 로컬 자동화에 등록된 담당자에게 HTML 검수 메일을 보낸다.
12. 실행 중인 Codex 작업에 게시물 제목, 카테고리, 비공개 링크, PNG 파일 링크와 이메일 발송 결과를 전달한다.

### HTML 검수 메일

- 제목: `[바이켐 블로그 검수 요청] {게시물 제목} 비공개 게시 완료`
- 본문: 게시물 제목, 카테고리, 게시 상태, 핵심 원고 내용, 한줄정리, 네이버 비공개 링크
- 형식: 모바일에서 읽기 쉬운 HTML 이메일
- 카드뉴스: 가능하면 PNG 첨부, 불가능하면 담당자가 열 수 있는 파일 링크 제공
- 수신 주소: 로컬 자동화 설정에서 관리하며 GitHub에는 기록하지 않음
- 목적: 담당자가 네이버에 로그인하지 않아도 이메일 본문만으로 주요 원고를 검수할 수 있게 함

## 3. 카드뉴스 기준

- 크기와 기본 템플릿은 `cardnews/README.md`를 따른다.
- 표지 1장, 핵심 내용을 설명하는 본문 카드, 필요한 경우 마무리 카드로 구성한다.
- 블로그 원고에 없는 새로운 제품 효능·수치·주장을 카드뉴스에 추가하지 않는다.
- 모바일에서 바로 읽을 수 있도록 문장을 짧게 쓰고 한 카드의 정보량을 제한한다.
- 카드뉴스 결과물은 게시물 폴더의 `cardnews/`에 PNG로 저장한다.

## 4. 실패·보류 처리

- 네이버 게시 전 이 Mac의 Codex 인앱 브라우저에 유효한 로컬 로그인 세션이 있는지 확인하고, 있으면 그대로 재사용한다.
- 네이버 로그인이 만료되면 아이디·비밀번호를 요구하거나 저장하지 않는다.
- 원고·대표사진·본문 이미지·카드뉴스 PNG까지 먼저 완성한다.
- 게시 단계만 보류하고 사용자에게 네이버 로그인 필요 사실을 알린다.
- 브라우저나 에디터 오류가 발생하면 공개 게시로 우회하지 않는다.
- 비공개 게시가 성공하지 않았으면 검수 완료 메일을 보내지 않는다.
- 이메일 전송에 실패하면 반복 발송하지 않고 Codex 작업에 실패 사실을 알린다.
- 사실 확인이나 제품자료가 부족하면 미확인 내용을 만들지 않고 `[사내 확인 필요]`로 남긴다.

## 5. GitHub와 Codex 자동화의 관계

이 문서는 자동화의 일정과 작업 규칙을 보관한다. Codex 앱에 등록된 실제 예약 작업의 활성 상태, 다음 실행 시각, 브라우저 로그인 세션은 GitHub에 자동 동기화되지 않는다.

새 컴퓨터나 다른 담당자 환경에서는 저장소를 내려받은 뒤 다음 조건으로 예약 자동화를 다시 만든다.

- 매주 화요일·목요일 오전 9시(Asia/Seoul)
- 회차별 블로그 1건 비공개 게시
- 게시 후 카드뉴스 PNG 제작
- 완료 결과를 해당 Codex 작업에 전달

네이버와 GitHub의 로그인 정보, 쿠키, 인증 코드와 API 키는 저장소에 커밋하지 않는다.

## 6. 로컬 로그인 세션 운영

- Codex 인앱 브라우저가 유지하는 네이버 세션은 해당 Mac에서만 재사용한다.
- 로그인 상태 유지 기간은 네이버 정책과 보안 판단에 따라 달라질 수 있으며 영구 로그인을 보장하지 않는다.
- 별도 게시 도구가 세션 파일 또는 브라우저 프로필을 만드는 경우 저장 위치는 `auth/`, `cookies/`, `browser-profile/`, `session/` 또는 `playwright/.auth/`로 제한한다.
- 위 경로와 `storage-state*.json`, `*.cookies.json`은 `.gitignore`에서 제외한다.
- 세션 파일을 GitHub, 메신저, 이메일과 공유 폴더로 전송하지 않는다.
- 자동화는 쿠키나 토큰 값을 출력·요약·로그 기록하지 않는다.
- 세션이 만료되면 담당자가 같은 Mac에서 네이버 로그인을 다시 완료하고 다음 실행부터 재사용한다.

## 7. 이메일 연결 운영

- 이메일 계정 연결과 실제 수신 주소는 Codex의 로컬 자동화 설정에서 관리한다.
- 저장소에는 이메일 주소, 인증 토큰, 앱 비밀번호와 SMTP 자격증명을 기록하지 않는다.
- 새 컴퓨터나 다른 담당자 환경에서는 이메일 연결과 검수 수신 주소를 다시 설정한다.
- 테스트 발송 후 제목, HTML 표시, 링크 접근과 첨부파일 열림 여부를 확인한다.
