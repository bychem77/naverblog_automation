# 바이켐 블로그·카드뉴스 주간 자동화 운영

> 이 문서는 예약의 설치·복원·보안만 설명합니다. 회차별 실행 순서는 `automations/BYCHEM_BLOG_AUTOMATION_PROMPT.md`, 콘텐츠 결과 기준은 `prompts/BYCHEM_NAVERBLOG_MASTER_PROMPT.md`만 따릅니다.

## 실행 일정

- 매주 화요일·목요일 오전 9시
- 기준 시간대: Asia/Seoul
- 회차별 블로그 1건
- 네이버 게시 상태: 비공개

## 저장소에 보관되는 항목

- `automations/bychem_blog_schedule.yaml`: 일정과 실행 환경
- `automations/BYCHEM_BLOG_AUTOMATION_PROMPT.md`: 실행 순서와 오류 처리
- `automations/RESTORE_PROMPT.md`: 다른 컴퓨터에서 예약을 복원하는 요청문
- `automations/local.settings.example.yaml`: 로컬 설정 형식의 예시

## 다른 컴퓨터에서 복원

1. 저장소의 최신 내용을 내려받습니다.
2. `automations/RESTORE_PROMPT.md`를 Codex에 전달합니다.
3. 동일한 이름의 예약이 있으면 중복 생성하지 않고 업데이트합니다.
4. 네이버와 이메일 계정을 해당 컴퓨터에서 직접 연결합니다.
5. 테스트 실행으로 비공개 게시, HTML 이메일과 첨부파일을 확인합니다.

GitHub에는 예약 정의만 저장됩니다. 실제 활성 상태, 다음 실행 시각, 브라우저 로그인 세션과 이메일 연결은 컴퓨터마다 별도로 설정해야 합니다.

## 로그인과 보안

- 유효한 로컬 네이버 세션은 같은 컴퓨터에서만 재사용합니다.
- 로그인 정보, 쿠키, 토큰, 인증 코드, 이메일 주소와 API 키는 GitHub에 저장하지 않습니다.
- 별도 도구가 세션 파일을 만들면 `.gitignore`에 등록된 로컬 인증 경로에만 보관합니다.
- 네이버 로그인이 만료되면 제작물은 저장하고 게시와 이메일을 보류합니다.
- 이메일 발송이 실패하면 자동으로 반복 발송하지 않습니다.

## 변경 방법

- 콘텐츠 스타일이나 편집 기준 변경: 마스터 프롬프트만 수정
- 예약 시간이나 실행 순서 변경: `automations/` 파일 수정
- 수신자 변경: GitHub가 아닌 해당 컴퓨터의 로컬 설정 수정

변경 후에는 `scripts/check_prompt_consistency.sh`를 실행하고 관련 파일만 커밋합니다.
